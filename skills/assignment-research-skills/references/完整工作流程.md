# 完整 Assignment 工作流程

本文件是完整工作流程、Rubric 追踪及证据规则的唯一详细维护源。用户版概览见 [`docs/完整工作流程.md`](../../../docs/完整工作流程.md)；可填写字段见 [`assets/作业规划与证据记录模板.md`](../assets/作业规划与证据记录模板.md)。字段含义和状态定义以本文件为准。

## 中文

### 1. 收集要求并确定范围

只根据当前 Assignment Brief、Rubric/Marking Scheme、相关 Lecture Notes、教师补充要求、提交规范和课程 AI 政策开展工作。摘录任务动词、交付物、目标章节、字数、来源限制、引用规则和截止日期。区分用户负责范围与未要求处理的章节。缺少关键要求、材料冲突或分工不明时，列出具体问题并先确认；不猜测，也不默认写完整作业。

历史作业只用于学习方法。旧作业中的文字、来源、数据、评分规则和教师政策不得自动复用；旧材料声称核验过的来源仍需按本次论点重新核查。

### 2. 选择追踪模式并建立 Rubric 映射

先逐项拆解 Rubric。原 Rubric 有编号时沿用其 ID；无编号时不伪造原始 ID，可按本次记录使用临时行号。

**精简模式（默认用于简单作业）：**一行对应一个评分项，在同一张表中记录评分要求、课程概念/论点、来源、原文证据位置、证据支持的具体主张、正文位置、状态和下一步行动。

**完整模式（仅在确有需要时）：**来源较多、一个来源支撑多项主张、需要多人协作或同一来源记录需复用时，另建来源台账，以来源 ID 关联 Rubric 行。不要为了表格完整而要求每个小型作业填写独立台账。

不适用的讲义概念标记“不适用”，不可强行关联。每项评分要求须有论点/任务回应位置；暂时无来源或证据时记录缺口，不用其他评分项的完成状态代替。

### 3. 使用统一字段和独立状态

模板字段见 [`assets/作业规划与证据记录模板.md`](../assets/作业规划与证据记录模板.md)。按以下定义记录，不合并状态：

| 状态对象 | 记录含义 | 可用状态 |
|---|---|---|
| 来源存在性 | 是否在可复查的出版者、期刊、机构或其他可靠记录中找到该作品 | 已找到记录（尚未核实）/ 存在性已核实 / 本次查询未找到（不代表不存在）/ 查询失败 / 记录冲突 / 待确认 |
| 书目信息准确性 | 作者、日期、标题、出版物/来源及 DOI 等适用字段是否与权威记录相符 | 已核实 / 部分核实 / 缺失 / 待确认 / 不适用 |
| 实际阅读范围 | 实际检查了哪些材料 | 全文 / 摘要 / 元数据 / 指定部分 / 未读 |
| 具体主张支持 | 已读材料实际支持所映射的主张到什么程度 | 直接支持 / 部分支持 / 间接支持 / 不支持 / 待确认 |
| Rubric 完成状态 | 当前作业内容对评分项的回应程度 | 达成 / 部分达成 / 缺失 / 待确认 |

只有存在可复查依据时，才把相应核验状态标为已核实。只读摘要或元数据时必须如实记录；不得声称阅读全文，也不得由 DOI、标题匹配或来源存在推断正文主张成立。若尚未读到足以判断支持关系的原文，主张支持状态为“待确认”。

### 4. 检索并整理证据

围绕具体主张设计少量查询，遵守教师的来源限制。优先采用本地已提供材料、官方出版方/机构网页及无需付费的公开资源。Crossref 可用于 DOI/书目元数据查询；OpenAlex 或 Semantic Scholar 仅在当前有免费访问额度且无需新建付费账户、购买 Key 或启用付费预算时使用。使用免费 API 时遵守服务条款和限额；遇到 429、限额提示、登录墙或服务不可用即停止该查询，记录“限额/查询失败”，改为人工访问免费公开页面或标“待确认”，不得自动切换到付费服务。不要为查询把完整作业、私人课程材料或无关个人信息发给外部服务，也不要读取或输出 API 密钥。

对每条拟用证据记录来源、原文定位（页码、段落、表格、章节或数据位置）、支持的具体主张、实际阅读范围、来源研究对象/年份、适用范围、限制及不同观点。主张支持状态使用“直接支持、部分支持、间接支持、不支持、待确认”；只有已读取且可定位的内容才能支持状态判断。只读摘要只能判断摘要明确说到的有限内容，全文支持保持待确认。DOI 存在、书目匹配或主题相关均不等于主张已获支持。证据不支持原主张时，应收窄措辞、补充来源或标待确认，不扭曲原文。

对于年报、财报、统计数据及表格中的关键数字，逐项记录具体主张、原始来源名称/年度、页码/表格、原始科目名称、报告期间、币种/单位、Company/Group 等口径、原始值、作业中的值、一致性/差额、第二次独立复核方法与结果、当前状态和限制。核对时逐一比对原表标题、列头、单位、期间和实体口径；不得把不同会计科目或 Company 与 Group 数值混用。第二次复核应重新定位原表或使用独立的原始页面/表格呈现，不得把重复查看同一搜索摘要算作独立复核。无法读取原始表、无法独立复核或来源间有差异时，保留“待确认/有差异”，列出差异和下一步，不自行选择一个值当作确认事实。模板见 [定量事实复核表](../assets/作业规划与证据记录模板.md)。

### 5. 分段写作

只处理用户指定的章节或段落。各段回应相应 Rubric 要求，提出清楚主张并解释课程概念和证据如何支持。对重要内容标明其性质：来源披露的事实、一般理论、作者推论或最终建议。一般理论只能提供分析框架，不能自动证明某公司的具体决策；商业建议需对照公司事实、理论适用条件及相关替代方案，并把证据支持和作者判断分开。区分事实、推断、建议和个人判断；不把相关性直接写成因果，不超出来源证据强度。修改时保留已完成的未指定部分。

英文正文使用清晰、自然、正式的本科生英文；按用户要求提供华文解释。润色须保留原意、证据强度、限定语和引用。

### 6. 引用规则

先检查当前 Coursework、Rubric 和教师要求；本次作业的明确指示优先。若未提供作业级格式要求，核对 TAR UMT Library 当前官方引用指南及课程/学科例外。TAR UMT Library 指南将 APA 7 列为主要风格，同时说明部分课程可能采用其他风格。只有在 APA 7 确认适用于当前作业时，才采用 [`APA 7 引用核查规则`](APA7引用核查.md)；适用规则不明时标「待确认」，不直接判违规。来源真实性、基本引用对应、APA 格式与论点证据支持是不同任务，不能互相替代。

### 7. 逐项最终审核

对 Rubric 的**每一项**输出单独结果，不以整体评价或总分代替。逐项核对：

1. Rubric 原始要求及对应的课程概念/论点；
2. 来源、书目信息、实际阅读范围和原文证据位置；
3. 证据支持的具体主张、适用范围和限制；
4. 正文对应章节/段落；
5. Rubric 状态（达成/部分达成/缺失/待确认）；
6. 缺口、待核实事项和下一步行动。

没有对应证据的项目不得标为达成。未实际执行的核查不得报告为已完成；没有评分方法或评分依据时不得虚构分数。

### 8. 交付报告

报告处理范围、逐项 Rubric 状态、实际使用的证据、来源核验与阅读范围、未完成事项、未执行的检查及用户需要人工完成的下一步。明确哪些结论来自已提供材料，哪些仍待核实。

## English

### 1. Collect requirements and set scope

Use only the current Assignment Brief, Rubric/Marking Scheme, relevant Lecture Notes, instructor instructions, submission rules, and course AI policy. Extract task verbs, deliverables, target sections, word count, source limits, citation requirements, and deadline. Confirm the user's assigned scope. When key requirements are missing, materials conflict, or responsibilities are unclear, list the questions and ask before proceeding. Do not guess or assume a complete assignment is requested.

Use past assignments only to learn methods. Do not automatically reuse their prose, sources, data, rubrics, or instructor policies. Recheck any old source against the current claim.

### 2. Choose a tracking mode and map the Rubric

Break down every Rubric criterion. Reuse an ID only when the original Rubric provides one; do not invent an original ID. A temporary row number may be used for tracking unnumbered criteria.

**Compact mode (default for simple assignments):** use one row per criterion to record the requirement, course concept/claim, source, exact source-evidence location, specific supported claim, document location, status, and next action.

**Full mode (only when useful):** create a separate source ledger with source IDs when there are many sources, one source supports multiple claims, or collaboration/reuse requires it. Do not require a separate ledger for every small assignment.

Mark an irrelevant lecture concept “not applicable.” Each criterion needs a claim or task response location. Record missing source/evidence as a gap; do not substitute another criterion's completion status.

### 3. Use consistent fields and separate statuses

Use the field structure in [`the planning and evidence template`](../assets/作业规划与证据记录模板.md). Keep these states separate:

| Status object | Meaning | Allowed status values |
|---|---|---|
| Source existence | Whether the work was found in a checkable publisher, journal, institutional, or other reliable record | Record found (not yet verified) / existence verified / not found in this search (does not prove nonexistence) / query failed / records conflict / to be confirmed |
| Bibliographic accuracy | Whether applicable author, date, title, publication/source, DOI, and other fields match authoritative records | Verified / partly verified / missing / to be confirmed / not applicable |
| Reading scope | What material was actually examined | Full text / abstract / metadata / specified portion / unread |
| Support for a specific claim | What the examined material actually supports and to what extent | Directly supported / partly supported / indirectly supported / not supported / to be confirmed |
| Rubric completion | How well the submitted work addresses the criterion | Met / partly met / missing / to be confirmed |

Mark a check as verified only when it has reviewable evidence. Label abstract or metadata review honestly. Do not claim full-text review or infer claim support from a DOI, title match, or source existence. If the inspected text is insufficient to assess support, mark claim support “to be confirmed.”

### 4. Find and organize evidence

Design a small number of searches around specific claims and follow instructor source restrictions. Prefer user-provided materials, official publisher/institution pages, and free public resources. Use Crossref for DOI/bibliographic metadata; use OpenAlex or Semantic Scholar only when free access is currently available without a paid account, purchased key, or paid budget. Respect service terms and limits. On HTTP 429, a limit notice, login wall, or unavailable service, stop that query, record “limited/query failed,” use a free public page manually if available, or mark the issue to be confirmed. Never fall back automatically to a paid service. Do not send a full assignment, private course material, or irrelevant personal information to an external service, and do not read or print API keys.

For each proposed piece of evidence, record its source, exact location (page, paragraph, table, section, or data location), specific claim, actual reading scope, study population/year, applicability, limitations, and differing views. Use these claim-support states: directly supported, partly supported, indirectly supported, not supported, or to be confirmed. Only examined, locatable material can support a status. An abstract supports only the limited content it explicitly states; full-text support remains to be confirmed. A DOI, matching bibliography, or topical relevance does not prove claim support. If evidence is insufficient, narrow the wording, find another source, or mark it to be confirmed; never distort the source.

For material figures from annual reports, financial statements, or statistical tables, record each claim, original source/title/year, page/table, original line-item name, reporting period, currency/unit, Company/Group or other scope, source value, assignment value, match/difference, independent second-check method and result, status, and limitations. Compare the table heading, column headers, unit, period, and entity scope. Do not mix accounting line items or Company and Group figures. A second check must independently relocate the original table or use another view of the primary source; rereading the same search snippet is not independent. If the original table is unavailable, independent checking is impossible, or sources conflict, retain “to be confirmed/discrepancy,” list the difference and next action, and do not select a value as confirmed. Use the [quantitative fact-check table](../assets/作业规划与证据记录模板.md).

### 5. Draft in stages

Work only on the section or paragraphs requested. Each paragraph should address its Rubric criterion, make a clear claim, and explain how concepts and evidence support it. Identify important content as a source-reported fact, general theory, author inference, or recommendation. General theory is an analytical framework; it does not automatically prove a company-specific decision. Business recommendations should compare company-specific facts, the theory's conditions of applicability, and relevant alternatives, separating source evidence from the author's judgment. Do not turn correlation into causation or overstate evidence. Preserve completed material outside the requested scope.

Use clear, natural, formal undergraduate English for assignment prose and provide Chinese explanations when requested. Editing must preserve meaning, evidence strength, qualifications, and citations.

### 6. Citation rules

Check the current Coursework, Rubric, and instructor requirements first; specific assignment instructions take precedence. If assignment-level rules are absent, consult the current official TAR UMT Library guide and programme/course exceptions. The TAR UMT Library guide identifies APA 7 as the main style while noting that some programmes may use another style. Use [`APA 7 citation checks`](APA7引用核查.md) when APA 7 is confirmed to apply; otherwise mark the applicable rule to be confirmed and do not declare a violation. Source verification, basic citation matching, APA formatting, and claim support are separate checks.

### 7. Review every Rubric criterion

Report each criterion **individually**; an overall evaluation or grade cannot replace criterion-level results. Check:

1. the original criterion and mapped concept/claim;
2. source, bibliographic status, actual reading scope, and exact evidence location;
3. the specific supported claim, scope, and limitations;
4. the corresponding section/paragraph;
5. Rubric status (met/partly met/missing/to be confirmed); and
6. gaps, unchecked items, and next actions.

Do not mark a criterion met without corresponding evidence. Do not report checks that were not performed as complete, or invent a grade without a grading basis.

### 8. Handover report

Report the scope reviewed, criterion-level results, evidence actually used, source-check statuses and reading scope, incomplete items, checks not performed, and the user's manual next steps. Distinguish conclusions supported by provided materials from items that remain unverified.
